# Ночной прогон reels-radar на сервере (этап 2)

Статус: выполнен 07.11 (go Некита), проба на 3 ссылках пройдена, приёмка кнопок в Telegram за Некитом. Итоги и ограничения: HANDOFF reels-radar. Основание: проба 07.11 (см. ниже) и просьба Некита, чтобы ночь шла, пока ноут выключен.

## Что показала проба (07.11, сервер Contabo)
- Две публичные рилс-ссылки скачались yt-dlp 2026.10.26 с сервера БЕЗ куки (9,0 МБ и 2,6 МБ). Куки аккаунта на сервер не отправлялись и не нужны.
- Не проверено: карусели /p/ (gallery-dl без логина), объём 60 за ночь (лимиты 429), закрытые и возрастные посты (нужен логин), устойчивость через неделю.
- OCR: RapidOCR PP-OCRv5 eslav даёт 0.859 доли слов эталона против 0.773 у Tesseract (30 картинок), но втрое медленнее и до 1,4 ГБ RAM; ночью это приемлемо. Скрипт и итоги: tools/server-trial/bench/ocr_rapid_vs_tesseract.py и README рядом.

## Что переезжает
Весь ночной прогон `reels_radar run`: скачивание (yt-dlp без куки, затем gallery-dl), кадры ffmpeg, расшифровка, OCR, `claude -p`. Дом: только запись заметок в vault.

## Шаги
1. Скачивание: цепочка без Playwright и без куки (на сервере нет pw-профиля). Условие по наличию файла куки и профиля, поведение дома не меняется.
2. Расшифровка: Groq вместо mlx_whisper (готовый `tools/video-research/transcribe_api.py` и опыт стт харвестера), куски по 15 минут, как у харвестера.
3. OCR: маленький скрипт-адаптер `ocr_rapid.py` по протоколу `ocr_bin` (пути картинок аргументами, блоки текста через `=====` в stdout), RapidOCR eslav. `run_ocr` и остальной код не меняются. Окружение: отдельное venv на сервере, модели в `~/ocrbench2/models` (88 МБ det + 7,9 МБ rec).
4. Claude: `claude -p` на сервере (claude 2.1.318, вход выполнен), `CLAUDE_BIN` в .env, FreeLLMAPI на сервере уже работает (запас при лимите). Модуль `tools/llm_fallback` нужен рядом с проектом: положить в `~/tools/llm_fallback`.
5. Слот и сторож: `should_yield` на сервере безвреден (флага нет). Расписание: systemd-таймер `reels-radar-night.timer`, 01:30 Asia/Ho_Chi_Minh (свободное окно, харвестер в 03:00), MemoryMax 3G (RapidOCR + Claude), Persistent=true.
6. Дом: `reels-night` убрать из `tools/slot/jobs.json` (копия .bak), чтобы не писать в старую radar.db.
7. Запись в Obsidian (без этого черновики будут некуда идти): пакеты как у харвестера, но без дублирования логики. Сервер при нажатии «записать/идея/вдохновение/откат» кладёт пакет в outbox (поля строки: code, title, body, summary, template, раздел, vault). Ноутовый applier (новый launchd-джоб `reels-radar-applier`, раз в 5 минут, лёгкий) собирает временную базу из одной строки и вызывает те же `write_note_to / write_idea / write_inspiration / rollback` из decisions.py и vault.py, читает результат (note_path, moc_line, decision, ...) и возвращает ack. Сервер обновляет статус по ack. Статус «в очереди» между нажатием и записью.
8. Меню разделов (`catalog`) на сервере читает зеркало vault. Нужно зеркало второго vault (Досуг) и подмена пути `vaults.dosug` в themes.yaml через переменную окружения. Зеркало main и extra0 уже подтягивается для харвестера.
9. Включить карточки на сервере (`RADAR_CARDS=1`) только после шагов 7-8 и приёмки.
10. Сторож: новый джоб applier в список NIGHT `resource-guard.sh`, вес замерить.
11. Откат: сервер `systemctl --user disable --now reels-radar-night.timer`, дом вернуть `reels-night` в jobs.json (радар-базу вернуть копией).

## Критерии проверки
- пробный прогон `run --limit 3` на сервере: 3 строки получили статус, без исключений, пик RAM ниже лимита;
- OCR-адаптер даёт то же число слов, что бенч, на 3 тестовых картинках;
- сквозная проверка на одной сохранёнке: черновик в карточке -> кнопка -> пакет -> ноутовый applier -> заметка в vault, MOC и холст обновлены -> ack -> статус «записано» -> откат возвращает;
- повторная доставка пакета не создаёт «(2)»;
- ночью запустился таймер и в `journalctl` есть сводка `{'draft': N, ...}`.

## Риски
- Instagram может начать резать IP дата-центра при объёме. Ночь при RATE встаёт на паузу до следующей, это уже заложено в pipeline. Закрытые и возрастные посты будут no_video; в дайджесте есть список «Нужен файл».
- Два записывающих процесса в одну radar.db нельзя: после шага 6 ночь и бот только на сервере.
- Лимит подписки Claude делится с харвестером; ночные окна разнесены (01:30 и 03:00).
- Vision-часть (кадры в Claude через Read) на сервере не проверялась, нужна пробная классификация.
