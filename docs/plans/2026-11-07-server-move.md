# Перенос reels-radar-bot и дайджеста на сервер (Contabo)

Статус: этап 1 и этап 2 выполнены 07.11, ждёт приёмки кнопок карточек в Telegram. Подробности: HANDOFF reels-radar, блок «07.11.2026 (вечер)».

## Причина молчания бота (установлено 07.11)
1. Бот не запущен: disabled в launchd, сторож снимал его при нехватке RAM (72 раза 25.10). Это главная причина.
2. Группа «Отписки» (-5544644805): бот там участник, privacy mode включён (can_read_all_group_messages=False), список команд у бота пуст. В группе команда доходит только в виде /clean@cucaramba_reels_radar_bot. В личке с ботом ограничения нет.
3. Токен один, отдельного «бота отписок» в проекте нет (в .env один BOT_TOKEN).

## Что меняется владелец данных
- sources.db (4158 аккаунтов, пометки чистки, /done): хозяин сервер. Дома `sources verify` ставится на паузу (он и так даёт 0, очередь 570), иначе две копии разъедутся.
- radar.db (карточки, статусы): хозяин остаётся дом (ночной сбор по Instagram и решения по карточкам). На сервер уходит копия только для чтения (дайджест, /status, /find).
- Карточки с кнопками «записать в Obsidian» (decisions.py, vault.py: заметка + строка в MOC + холст + откат) на сервере в этом этапе НЕ работают: нет vault. Очередь карточек сейчас почти пуста (draft 2, ночной сбор отдаёт 0). Этап 2 (по желанию): пакеты записи как у харвестера.

## Этап 1 (минимум, без доработок функционала)
1. Сервер: каталог ~/reels-radar, код rsync (без data/, .venv, logs, pw-profile), uv venv, .env через scp (токен не показывать).
2. Сервер: sources.db и копия radar.db через sqlite backup, проверка целостности и счётчиков (4158 аккаунтов).
3. Конфиг: пути reels_tools/reels_pipeline/ocr_bin на сервере не нужны боту; проверить, что load_settings не падает, при необходимости подставить заглушки. Отключить pump карточек на сервере (флаг), чтобы бот не слал кнопки, которые не сработают.
4. Юнит systemd --user с MemoryMax=300M, Restart=always. Запуск ТОЛЬКО после того, как дома бот выключен (токен в двух местах не держать, Telegram отдаёт апдейты одному getUpdates).
5. Дома: оставить com.cucaramba.reels-radar-bot disabled (уже), снять из сторожа/стартёра остатки, пометить паузу verify (слот).
6. Дайджест: юнит-таймер на сервере вс 19:00 (Asia/Ho_Chi_Minh), читает копию radar.db. Копию радара раз в 5 минут обновляет существующий applier на ноуте (sqlite backup и rsync на сервер, односторонне).
7. setMyCommands: зарегистрировать /clean /cleanup /cleanup_list /done /status /find /help (меню в Telegram). Не обязательно, но убирает путаницу.
8. Приёмка с Некитом: в личке с ботом /status, /clean (ссылки пачками по 10), /done user (отметка в sources.db на сервере), потом то же в группе «Отписки» через @-упоминание.

## Критерии проверки
- процесс на сервере живой, NRestarts=0, память ниже лимита;
- /clean отдаёт список из sources.db сервера, /done меняет статус (проверка по базе на сервере);
- на ноуте нет процесса бота и нет второго getUpdates (409 Conflict в логе = провал);
- digest --send на сервере в пробном запуске шлёт сообщение со счётчиками;
- откат: на сервере systemctl --user stop, дома bootstrap + enable/disable по правилам CLAUDE.md (sources.db вернуть копией).

## Риски
